>
> **本仓库与代码仓库的对应关系**：规范规定 code 侧的协议行为与可调参数；代码侧在入口处声明"本实现遵循《ZT-DSP 协议总指导》"。双方不靠版本号绑定。

## 版本说明

本项目有**两个版本号**，以及一套**文档-代码双向声明**：

- **docs 版本（1.0.0）**：本文档仓库自身的修订号，写作 `docs 1.0.0`。不参与网络通信。
- **code 版本（1.0.0）**：代码仓库的实现与协议行为版本，写作 `code 1.0.0`。指认具体实现时用实现标识，形如 `ZT-DSP_<语言前缀>-<主.次.修订>`——Python 实现为 `ZT-DSP_PY-1.0.0`，Rust 实现为 `ZT-DSP_RS-1.0.0`。不同语言的实现可共用同一版本号，靠语言前缀区分。
- **双向声明**：文档侧（`spec/` 头部）声明"本文档管 code 的哪些设置"；代码侧（`zt_dsp_py/version.py` 的 `FOLLOWS_DOC`）声明"本实现遵循哪份文档"。**双方不靠版本号绑定**。

**握手帧中不携带任何版本串**：阶段一参数 JSON 与阶段四 AAD 均不含版本或协议标识字段。对端是否遵循同一份文档，由阶段三确认标签校验体现。

**现行版为准**：实现以附录 F（线上逐字节规范）与附录 H（状态机/超时矩阵）为准绳。

## 仓库边界

- **本仓库（ZT-DSP-docs）**：协议规范、术语基线、设计资产、仓库自身配置。
- **代码仓库（ZT-DSP-client）**：官方实现 `zt_dsp_py/`（Python）与 `zt_dsp_rs/`（Rust），以及运行脚本与工程文件。
- **服务端仓库（ZT-DSP-server）**：服务端实现的骨架，目前只有占位说明，**尚未开始实现**；其版本标签沿用 `server-v*`。
- 文档正文里出现的 `zt_dsp_py/`、`zt_dsp_rs/` 路径**指代码仓库内的官方实现目录**，不在本仓库。
- 三个仓库不互相搬运：文档改动进本仓库，代码改动进代码仓库，服务端改动进服务端仓库。
