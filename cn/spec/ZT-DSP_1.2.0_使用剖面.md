# ZT-DSP 使用剖面

核心规范定义「怎么安全地互相证明并协商出密钥」。
**剖面**定义「拿它来干什么，以及为此必须额外做到什么」。

本文件定义两个剖面：

| 剖面 | 一句话 | 状态 |
|---|---|---|
| **[通讯剖面](#2-通讯剖面)** | 双方共享一个房间号，消息对服务端不可见、对旁观者不可关联 | 已实现，见 1.1.0 总指导 |
| **[鉴权剖面](#3-鉴权剖面)** | 双方证明持有同一 PSK，拿到认证结论与派生密钥，**不必建立通讯会话** | 新增 |

---

## 1. 剖面怎么用

### 1.1 三条硬规则（来自核心 §9）

1. **只能追加**：剖面可以加要求、加语义、加威胁条目，**不能削减核心**。
2. **不能削弱认证**：不得跳过阶段、允许降级、复用已销毁的密钥。
3. **不能把核心的「不提供」变成「已提供」**：核心 §2.2 列出的性质（后妥协自愈、第三方可验证凭据、抗量子等），剖面一律不能声称已提供。

### 1.2 剖面标识

实现必须显式声明所运行的剖面，**跨剖面互操作不被假定**。

---

## 2. 通讯剖面

### 2.1 适用范围

两方在**可能不可信的中间网络**上交换消息，且要求：

- 服务端（或任何中间人）**看不到消息内容**；
- 服务端**无法把同一会话的两条消息关联起来**；
- 旁观者**无法确认两端是否在通讯**；
- 身份通过**令牌**证明，而不是通过连接来源。

### 2.2 对核心的使用

使用**全部四个阶段**：阶段一身份声明（含房间号与参数协商）→ 阶段二密钥协商 → 阶段三确认 → 阶段四加密帧流。

### 2.3 附加要求（**不属于核心**）

| 要求 | 内容 | 为什么不在核心里 |
|---|---|---|
| **服务端静默丢弃** | 服务端无法路由到具体接收者时，**必须表现得像正常转发一样丢弃**（不返回错误、不拒绝连接） | 这是对中间人的防御，只在有服务端转发时才有意义 |
| **随机填充** | 数据帧载荷长度必须随机化，避免长度泄漏消息大小 | 元数据防护，与应用语义绑定 |
| **服务端不可关联** | 会话标识必须与身份解绑，且不得在同一会话内复用 | 需要身份令牌体系配合 |
| **房间号派生出 PSK** | 房间号经 KDF 派生出 PSK，房间号原文不上线 | 属身份目录的设计 |
| **身份令牌（TCA）** | 由权威方签发、含绑定字段、带期限 | 依赖外部信任体系 |

### 2.4 追加的威胁模型条目

| 攻击 | 要求 |
|---|---|
| 服务端枚举房间 | 房间号空间足够大；服务端只见派生后的 PSK，不见原文 |
| 服务端关联会话 | 会话标识与身份解绑；同一 PSK 的两次连接不得产生可关联的公开字段 |
| 旁观者确认通讯发生 | 帧长度随机化，且无协议级错误信号 |

### 2.5 不适用情形

- 需要离线阅读历史消息（无状态设计，不缓存）。
- 需要消息可靠送达或重放语义（fail-closed 零丢包容忍）。
- 需要跨会话搜索或集中审计。

## 3. 鉴权剖面

### 3.1 为什么这是独立剖面

ZT-DSP 从第一天起就以 PSK 为信任根：**知道同一个 PSK 即同一身份**。
因此「用 ZT-DSP 鉴权」不需要新增协议，只需要**把核心层单独跑完**：

```
阶段一  身份声明（可选） + 参数/版本协商
阶段二  密钥协商
阶段三  确认          <-- 到这里，认证已经完成
阶段四  加密帧流      <-- 通讯用途才需要；鉴权用途可不用
```

### 3.2 适用范围

- 设备接入服务（设备与服务共享 PSK）；
- 点对点配对（两个设备首次相遇时通过带外方式交换 PSK）；
- 人员登录服务（PSK 存于硬件密钥或安全元件）；
- 任何「双方各持一把相同钥匙」的准入场景。

### 3.3 对核心的使用

| 项 | 取值 |
|---|---|
| 阶段 | 一至三为必需；四为可选 |
| 传输 | 任意有序可靠字节流；**可短连接**，无需长连接 |
| 会话 | 单次认证导出的会话密钥可被应用复用，**或立即丢弃** |
| 顺序语义 | 不适用（无数据阶段） |

### 3.4 成功判据

与核心 §8 一致，三条同时成立：

1. 双向确认标签均通过（双方持有同一 PSK 且 transcript 一致）；
2. 参数逐项一致（含 `proto` 版本）；
3. 身份声明（若使用）通过验证。

**任一条不成立 → 立即终止并清除全部密钥材料**。

### 3.5 剖面职责（核心不管的）

| 事项 | 为什么归剖面 |
|---|---|
| **PSK 的分发** | 核心只假定双方已通过带外方式共享 PSK |
| **PSK 的存储** | 属宿主安全：安全元件、文件权限、口令管理器 |
| **PSK 的轮换与吊销** | 需要生命周期管理，不属协议 |
| **失败计数与锁定** | 核心不防 DoS，限速必须由服务端实施 |
| **向第三方出示凭据** | 核心明确不提供；若需要，属独立设计 |

### 3.6 追加的威胁模型条目

| 攻击 | 要求 |
|---|---|
| 暴力枚举 PSK | PSK 具备足够熵；**服务端必须限速**（核心不提供） |
| 重放旧的认证交互 | 阶段二每次使用全新临时密钥与盐；确认标签覆盖 transcript |
| 降级到旧协议 | `proto` 必填且缺失即拒（核心 §5.3） |
| 用弱密钥参数接入 | `key_len` 下限 256 位，对对端提议同样强制 |
| 会话密钥被跨会话复用 | 会话材料逐会话派生；应用层不得跨会话缓存 |

### 3.7 明确不做

- 不产出可供**第三方**离线验证的令牌（SPIFFE / WebAuthn 类）。
- 不提供**用户级身份**：认证的是「持有 PSK 的那一端」，不是「某个人」。
- 不提供吊销查询：PSK 作废需带外完成。
- 不提供后妥协自愈：认证本身无状态，泄露后的补救靠轮换。

### 3.8 失败处理

- 失败**必须显式**，不得静默降级到「只做单向认证」。
- 失败后**不得自动重试**同一 PSK（避免被用作在线猜测预言机）；重试策略由服务端限速控制。

## 4. 剖面组合

两个剖面可**串联**：先跑鉴权剖面拿到会话密钥，再用同一材料建立通讯剖面的帧流。

```
鉴权剖面（阶段一~三）  ->  认证通过 + 会话材料
                              | 可选
通讯剖面（阶段四）     ->  在该材料上传输消息
```

> 此时**后妥协自愈仍然不存在**（核心 §2.2）：会话材料泄露后，该会话后续流量均可读。

---

## 5. 新增剖面的准入

写一个新剖面前必须答出：

1. **用途**——它解决什么问题，核心加什么也不够？
2. **追加了什么**——要求 / 语义 / 威胁条目，各是哪几条？
3. **是否覆盖核心假设**——若是（例如改用不可靠传输），必须逐条标注被覆盖的条款与理由。
4. **是否只是换应用**——如果差异只在「载荷长什么样」，那是**应用**，不是剖面。

> 第 4 条最容易被滥用：**换载荷不构成剖面**。剖面只用于改变协议行为或威胁模型。
