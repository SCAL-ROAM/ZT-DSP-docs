# ZT-DSP 核心规范（通用层）
> **为什么文件名不带版本号**：草案不是发布。本项目的版本契约（`ZT-DSP-client` 的 `version.py`）规定文档版本仅用于文档自身的修订计数、**不参与网络通信**，且**兼容性从不由版本号相等来表达**。因此「下一版是 1.2.0」在本项目里根本推不出来。评审通过、真要取代 1.1.0 总指导时，再按实际改动定版本——线上真正有意义的版本号是 `proto` 字段，当前为 `1.1.0`，与本核心保持一致。

本文定义 ZT-DSP 的**核心协议**：一套**与传输无关、与应用无关**的双方认证与密钥协商机制。
具体用途（实时通讯、服务接入、设备配对、文件交换……）由**使用剖面**在核心之上声明，见 [ZT-DSP 使用剖面](ZT-DSP_draft_使用剖面.md)。

### 0.2 为什么把 PSK 摆在第一位

ZT-DSP 从第一天起就是**基于预共享密钥（PSK）**的：会话密钥的根材料是 `PSK ‖ X25519 协商值`。
这意味着协议本身已经具备**鉴权**语义：

- **持有 PSK 即持有身份**。知道同一个 PSK 的双方互相认证，不需要任何证书、目录或 CA。
- **认证与密钥协商是同一件事**，不是两件事。做不到「只认证不建会话」，也没必要分成两步。
- 因此「用 ZT-DSP 做鉴权」不是新增功能，而是**把核心层单独使用**：跑完认证阶段即拿到认证结论与派生材料，不必进入数据阶段。

本规范因此把「双方相互认证」列为**第一目标**，而不是通讯的附属品。

## 1. 术语

| 术语 | 含义 |
|---|---|
| PSK | 预共享密钥。双方事先以带外方式获得的高熵对称秘密，是唯一的信任根 |
| 认证（authentication） | 双方证明自己持有同一 PSK，且第三方无法冒充任一方 |
| 密钥协商（key agreement） | 双方各自产生临时密钥贡献，协商出双方一致、第三方不可计算的共享材料 |
| 会话（session） | 一次核心协议运行的结果：认证结论 + 会话密钥 + 会话标识 |
| 通道（channel） | 在会话之上承载有序字节流的抽象，与具体传输无关 |
| 帧（frame） | 通道上的一个完整协议单元，含定长头与载荷 |
| 剖面（profile） | 在核心之上声明的用途约束：追加要求、追加语义、追加威胁模型 |
| 落地时间 | 剖面可以声明的、用于新鲜性判定的本地时钟信息 |

> 术语约定：本文用「会话」指协议运行结果，用「通道」指承载；**不使用「通讯」作为核心层术语**——通讯只是剖面之一。

## 2. 目标与非目标

### 2.1 目标（按优先级）

1. **双方相互认证**：基于 PSK，双方互相证明持有密钥，抵抗中间人与冒充。
2. **密钥协商**：产生第三方不可预测的会话密钥。
3. **前向保密**：会话密钥泄露后，已建立的会话流量不可回溯解密。
4. **防重放与防乱序**：旧帧、重放帧、伪造帧一律被识别并拒绝。
5. **版本与参数可协商且不可静默降级**：双方能就参数达成一致，任何降级企图都必须显式失败。
6. **失败即终止**：任何认证失败、完整性失败或协议违规，立即清除全部密钥材料并结束会话。

### 2.2 非目标（**本规范不提供**，引用时不得含糊）

| 不提供的性质 | 说明 |
|---|
| **后妥协自愈（PCS）** | 棘轮是**纯对称哈希链**，不含 DH 分量。一旦某时刻的会话密钥泄露，攻击者可解密该会话**此后全部**流量，只有重新协商才能恢复 |
| 第三方可验证的会话证明 | 本规范只做**双方之间**的认证。不导出可供第三方离线验证的令牌（类似 SPIFFE / WebAuthn 的信任绑定） |
| 抗量子 | KEM 为 X25519。迁移路径见 §11 |
| 拒绝服务防护 | 本规范不防 DoS。攻击者可以丢弃、延迟、伪造连接尝试 |
| 流量形状隐藏 | 帧长度、方向、时序可见。填充策略属于剖面（通讯剖面要求随机填充） |
| 多方/群组 | 仅两方。多方需要独立的群组协议 |
| 匿名性 | PSK 认证意味着「知道同一个 PSK 即同一身份」，这是特性不是缺陷 |

> §2.2 是本规范的**硬约束**。下游文档、实现或宣传材料若引用 ZT-DSP，**不得暗示本表所列性质**。

## 3. 威胁模型

### 3.1 攻击者能力

- 完全被动：可记录全部分帧，包括所有明文头字段。
- 完全主动：可在任意时刻注入、删除、重排、复制分帧；可冒充任一方发起新会话。
- **可完全控制传输与中继**：传输层（包括所谓「服务端」）由攻击者实现。
- **不可算**：无法从会话材料反推 PSK（除非 PSK 本身弱，见 §3.3）。

### 3.2 攻击面与对应要求

| 攻击 | 核心要求 |
|---|
| 窃听 | 全程无明文密钥材料；会话密钥由 PSK 与 DH 共同导出 |
| 中间人 | 确认标签覆盖完整 transcript；对端身份声明进入 transcript |
| 重放 | 单调序号 + 时间窗 + 认证载荷三者合一；旧帧一律拒绝 |
| 篡改 | AEAD 认证覆盖序号、会话标识与全部载荷 |
| 降级 | 版本与参数是 transcript 的一部分；不匹配即失败 |
| 跨会话关联 | 会话密钥逐会话派生；会话标识与身份解绑（是否由剖面保证，见 §8） |

### 3.3 明确承认的风险

- **弱 PSK 是致命的**：低熵 PSK 可被离线穷举。核心规范无法从协议层修复，只能在部署侧保证 PSK 熵。
- **PSK 泄露即身份泄露**：持有 PSK 即可冒充。轮换与吊销**不属于**核心规范。
- **DoS 不在防护范围**：攻击者可阻止会话建立或维持。

## 4. 协议概览

### 4.1 阶段

```
阶段一  身份声明（可选）    双方声明身份 + 协商参数 + 版本
阶段二  密钥协商            盐 + 双方临时公钥 → 会话密钥材料
阶段三  确认                双向确认标签，证明双方持有同一 PSK 且 transcript 一致
阶段四  加密帧流（可选）    在通道上传输认证帧
```

- **认证用途只需阶段一至阶段三**。阶段三成功即认证通过，会话密钥可用即完成。
- **通讯用途使用全部四个阶段**。
- 阶段四对本规范是可选的：核心不要求会话必须产生流量。

### 4.2 传输无关性

核心规范只要求传输提供**有序、可靠的字节流**：

- 不指定 TCP / UDP / QUIC / TLS。
- 不要求全双工，不要求同时读写。
- 不规定握手次数上限（由部署/剖面决定）。
- 帧边界由协议自身的长度字段给出，传输不需要消息边界语义。

若某剖面需要不可靠传输（如 UDP），**必须由该剖面补齐重传、乱序容忍与会话恢复规则**——核心的「乱序即终止」语义不适用于不可靠传输，剖面需显式覆盖该规则。

### 4.3 状态机

```
IDLE ──阶段一──> ANNOUNCED ──阶段二──> AGREED ──阶段三──> CONFIRMED ──阶段四──> ESTABLISHED
  │                   │                │                │                  │
  └───────────────────┴────────────────┴────────────────┴──────────────────┘
                                  任一步失败 → 终止（清除全部密钥）
```

**终止是终态**：不可恢复、不可回退、不可重放进入。重新通信必须从 `IDLE` 重新开始。

## 5. 密码学套件与参数协商

### 5.1 固定套件

| 项 | 取值 | 约束 |
|---|---|---|
| KEM | X25519 | 唯一允许值 |
| AEAD | AES-256-GCM | 唯一允许值（256 位密钥，禁止 128 位协商） |
| 哈希 | SHA3-256 / SHA3-512 / SHA2-256 / SHA2-512 | 白名单，禁止 MD5/SHA-1 |
| KDF | HKDF-SHA3 | 派生会话材料 |
| 签名 | Ed25519 | 仅用于身份声明（可选阶段），不参与密钥派生 |

### 5.2 参数与版本

阶段一的参数集（JSON，键字典序、紧凑分隔符）至少包含：

| 参数 | 含义 | 策略 |
|---|---|---|
| `proto` | 协议版本 | **必填**。缺失即判非法，**不做回退猜测** |
| `key_len` | 会话密钥长度 | **下限 256 位**，对对端提议同样强制 |
| `window` | 落地时间窗 | 双方一致 |
| `hash` / `aead` | 套件选择 | 白名单内，双方一致 |

比对顺序固定，**版本优先**：任一项不一致即报告该项，其中 `proto` 排第一。

### 5.3 降级防护

1. `proto` 缺失 → 判参数非法并终止（**不猜老版本**）。
2. `proto` 不在支持集合 → 判参数非法。
3. 参数集整体进入 transcript，被阶段三确认标签覆盖 → 改写任一参数都会导致确认失败。
4. `key_len` 低于下限 → 判参数非法（防止明文协商参数被改写为弱密钥）。

## 6. 密钥派生

### 6.1 材料

```
mk        = HKDF(PSK ‖ DH, INFO_MK, salt)        // 会话主密钥
anchor    = HMAC(mk, INFO_ANCHOR)                // 双向确认材料
ek        = HKDF(mk ‖ anchor ‖ role, INFO_EK)    // 方向相关初始密钥
session_id = HKDF(anchor, INFO_SID)              // 会话标识（明文可见）
```

`DH = X25519(本方临时私钥, 对端临时公钥)`。

### 6.2 逐帧密钥推进

```
msg_key   = ek                                 // 当前帧的 AEAD 密钥
ek_next   = HKDF(ek ‖ next_seed, INFO_EK_ROTATE)
```

每个帧携带自己的 `next_seed`，因此**密钥随帧推进并逐帧销毁**：拿到第 n 帧密钥不足以解密第 n+1 帧。

### 6.3 必须承认的局限

- 这是**纯对称链**，没有 DH 参与 → **无后妥协自愈**（§2.2）。
- `ek` 同时充当 AEAD 密钥与下一次推进的输入。成熟设计通常拆分 root / chain / message 三层，**消息密钥绝不回流**。本规范维持现状以保持与已归档实现一致，**改进方向见 §11**。

## 7. 帧与通道

### 7.1 帧头（定长）

| 字段 | 长度 | 说明 |
|---|---|---|
| `session_id` | 16 B | 会话标识（明文） |
| `seq` | 8 B | 单调序号（明文，同时作为 AEAD nonce 基础） |
| `ct_len` | 4 B | 密文载荷长度（明文） |

### 7.2 载荷

```
timestamp(8) ‖ fmt(1) ‖ 身份声明/载荷 ‖ [填充 ‖ pad_len(2)] ‖ next_seed(32)
```

全部载荷（含时间戳、身份声明、`next_seed`）都在 AEAD 内，**明文头只有会话标识、序号与长度**。

### 7.3 顺序与重放

- 接收方要求 `seq` **严格递增**。
- `seq ≤ 已收最大值` → **立即终止会话**。
- 时间戳超出落地窗但认证通过 → **仅丢弃该帧明文，不终止会话**（容忍时钟漂移）。
- 认证失败（AEAD 不匹配）→ 终止。

> 严格递增语义意味着**零丢包容忍**：任何乱序或重复都结束会话。这是刻意的 fail-closed 选择；剖面若需要不可靠传输，必须覆盖该规则（§4.2）。

## 8. 认证结论

### 8.1 成功判据

阶段三完成且：

1. 双向确认标签均校验通过（证明双方持有同一 PSK 且 transcript 一致）；
2. 参数集逐项一致（含 `proto`）；
3. 对端身份声明（若使用）通过验证。

**三者同时成立**才算认证通过。任何一项失败 → 终止并清除密钥。

### 8.2 可用于鉴权的输出

认证通过后，调用方可获得：

| 输出 | 用途 |
|---|---|
| 会话密钥材料 | 直接用于本次会话的加密通信 |
| 会话标识 | 本次会话的句柄，**不可跨会话关联到身份**（除非剖面要求） |
| 认证结论 | 「对端持有同一 PSK」这一布尔事实 |

⚠ **本规范不产出可供第三方验证的凭据**（§2.2）。若调用方需要「向某个服务证明自己走过本认证」，那是**剖面或应用层**的职责，不在核心范围内。

## 9. 剖面机制

### 9.1 剖面能做什么

剖面**只能追加**，不能削减核心：

- 追加**要求**（例如：帧长度必须落在随机化区间内）。
- 追加**语义**（例如：如何把身份令牌映射成路由标识）。
- 追加**威胁模型条目**（例如：服务端可关联会话标识）。
- 在明确标注的前提下**覆盖**核心的传输假设（§4.2 的不可靠传输）。

### 9.2 剖面不能做什么

- 削弱核心的认证强度、跳过阶段、允许降级。
- 复用或延长已销毁的密钥材料。
- 把核心的「不提供」清单（§2.2）变成「已提供」。

### 9.3 剖面标识

剖面由实现显式声明并应纳入配置一致性比对；跨剖面互操作**不被假定**。

## 10. 版本与兼容

- 协议版本在 `proto` 字段协商，见 §5.2。
- 版本改变 = 参数改变 = 必须重新协商；不存在「同一会话内切版本」。
- 本规范与 [1.1.0 总指导](ZT-DSP_1.1.0_总指导.md) 的派生材料一致，因此**参数一致时可互通**。
- 新增套件时**新增版本**，不得在旧版本内静默启用。

## 11. 已知局限与演进方向

| 局限 | 影响 | 演进方向 |
|---|---|---|
| 无后妥协自愈（纯对称链） | 密钥泄露后该会话全程可读 | 在数据面引入周期性 DH 重协商，形成双棘轮 |
| `ek` 兼任消息密钥与推进输入 | 单点密钥泄露连锁到全链 | 拆分 root / chain / message 三层 |
| 无第三方可验证凭据 | 无法接入「出示凭据」类体系 | 剖面级令牌格式（本规范明确不提供） |
| KEM 为 X25519 | 抗量子不足 | 双 KEM 组合过渡，需同步引入版本面 |
| 零丢包容忍 | 不适合不可靠传输 | 剖面覆盖 + 会话恢复机制 |
| 无吊销 | PSK 泄露后无法作废 | 属部署/CA 体系，不属核心 |
