# 符合性判定指南

> 读者：审计方、监管与合规评估方。
> 本文件只回答一件事：一份实现算不算符合 ZT-DSP 1.0.0。

## A.1 三档判定

| 等级 | 条件 |
|---|---|
| **符合** | 通过附录 C.1 全部条目、附录 J 全部向量、附录 F 字节布局逐字节一致 |
| **部分符合** | 只实现第 4 册的某个子集，且逐条列明未实现的 MUST 条目 |
| **不符合** | 未通过附录 C.1、任一向量不一致、或附录 F 存在字节级偏差 |

判定口径来自规范第零部分 0.3。本文件不新增要求。

## A.2 审计五步

1. 取被审实现声明的实现标识，格式 `<语言>_<版本>`。
2. 跑附录 C.1 全部自检条目。
3. 跑附录 J 全部测试向量，逐字节比对输出。
4. 比对附录 F 的字节布局，不看功能、只看字节。
5. 按 A.1 出结论，结论必须同时写明实现标识与被判定的文档版本。

## A.3 需要被审方交的材料

| 材料 | 用途 |
|---|---|
| 实现标识 | 定位被审对象 |
| 声称的文档版本 | 决定按哪一版判 |
| 向量通过记录 | 复核第三步 |
| 源码或可执行文件 | 复核第四步 |

## A.4 判定表

| IF | THEN |
|---|---|
| 未给实现标识 | 自称不成立，不进入判定 |
| 任一向量输出不一致 | 不符合 |
| 附录 F 存在字节级偏差 | 不符合 |
| 只实现子集且已列明未实现的 MUST | 部分符合 |
| 只实现子集且未列明 | 不符合 |

## A.5 审计必做命令

审计方需要能跑的二进制，因此构建算必做项，不属可选项。

1. 构建参考实现：在 `ZT-DSP-client/zt_dsp_rs/` 下跑 `cargo build --release`。
2. 跑测试向量：在 `ZT-DSP-client/zt_dsp_py/` 下跑 `python -m pytest -q tests/test_vectors.py`。
3. 跑跨实现互通：在 `ZT-DSP-client/zt_dsp_rs/` 下跑 `python interop_test.py`，看末行是否为 `[[ok]] interop suite passed`。
4. 跑本仓结构自检：在 `ZT-DSP-docs/` 下跑 `python scripts/check.py`，看是否九项全 PASS。

四条命令都带工作目录。缺一条，第四步的结论不可复现。

## A.6 不在判定范围

| 项 | 说明 |
|---|---|
| 安全强度 | 本文件只判符合性，不判安全性 |
| 代码质量 | 与互操作无关 |
| 性能 | 规范未规定性能指标 |
| 第三方专利状态 | 见附录 K 与 `cn/DEFENSIVE-PUBLICATION.md` |

审计结论不得越出本表。越界判定不成立。
